# OseledkoYYTest1 — каталог товарів та інформація про SharePoint-сайт

Вебчастина на SharePoint Framework (SPFx), яка отримує дані з двох джерел та відображає їх у п’яти окремих секціях:

1. **Products** — каталог товарів із відкритого API DummyJSON.
2. **SharePoint site** — відомості про поточний SharePoint-сайт через PnPjs.
3. **SharePoint lists** — видимі списки поточного SharePoint-сайту через PnPjs.
4. **User lookup** — пошук запису за ID у списку `Users` через PnPjs.
5. **Create user** — створення нового запису у списку `Users` через PnPjs.

Інтерфейс і повідомлення — англійською мовою. Значення з API відображаються мовою джерела без автоматичного перекладу. Коментарі до функцій і класів — українською.

## Технології

| Складова | Версія / призначення |
| --- | --- |
| SharePoint Framework | 1.23.2 |
| React / React DOM | 17.0.1 |
| TypeScript | 5.8.x |
| Node.js | `>=22.14.0 <23.0.0` |
| Heft | Збирання, перевірки та пакування рішення |
| Jest | Автоматизовані тести сервісів і форми |
| SCSS Modules | Стилі компонентів |

Запити виконуються безпосередньо в браузері. Окремий сервер для обробки API-запитів не потрібен. Для каталогу використовується `fetch`, а для SharePoint-сайту — PnPjs із контекстом SPFx.

## 1. Каталог товарів — Products

### Що відображається

Кожен рядок містить зображення, категорію, назву, опис і ціну товару. Ціна форматується за локаллю `en-US`, із двома знаками після десяткової крапки. Позначення валюти не додається, оскільки відповідь API не містить окремого поля валюти.

Кнопки керування:

- **Refresh** — повторно завантажити поточну сторінку.
- **Previous** — перейти до попередньої сторінки.
- **Next** — перейти до наступної сторінки.
- **Retry** — повторити запит після помилки.

Заголовок можна змінити в панелі властивостей вебчастини через поле **Title**. Назва джерела, підзаголовок, лічильник товарів і номер сторінки не відображаються.

### Як працює завантаження

Після відкриття вебчастини автоматично завантажуються перші 20 товарів:

```http
GET https://dummyjson.com/products?limit=20&skip=0&select=title,description,category,price,thumbnail
```

Авторизація не потрібна. Параметр `limit` задає кількість записів, а `skip` — зміщення. Під час переходу між сторінками зміщення змінюється на 20. Значення `total` з відповіді визначає, чи доступна наступна сторінка.

Сервіс `DummyJsonProductSource` перевіряє HTTP-статус і структуру даних. Компонент показує стан завантаження, порожній результат або повідомлення про помилку. Тайм-аут запиту — 15 секунд. Під час зміни сторінки або видалення компонента попередній запит скасовується через `AbortController`.

## 2. Відомості про сайт — SharePoint site

Секція розміщена над каталогом товарів і працює незалежно від нього. Вона автоматично завантажується разом із вебчастиною та показує відомості про сайт, на сторінці якого розміщено вебчастину.

### Запит через PnPjs

`PnpSiteInfoSource` створює клієнт PnPjs із `SPFx(this.context)` та виконує запит до SharePoint REST API для поточного вебсайту. Авторизація використовується з контексту SharePoint: окремо вводити, зберігати або передавати токен не потрібно.

Користувач бачить лише ті дані, на які має доступ у SharePoint. Якщо доступу немає або запит не вдався, секція відображає безпечне повідомлення про помилку без технічних деталей відповіді.

### Результат

| Підпис у віджеті | Поле відповіді |
| --- | --- |
| Display name | `displayName` |
| Name | `name` |
| Description | `description` |
| Site ID | `id` |
| Web URL | `webUrl` |
| Hostname | hostname адреси поточного сайту |
| Created | `createdDateTime` |
| Last modified | `lastModifiedDateTime` |

Дати відображаються англійською мовою в часовому поясі UTC. Для відсутніх необов’язкових значень виводиться **Not provided**. Розділ **JSON response** показує повну нормалізовану відповідь.

### Стан секції

- Запит виконується автоматично після монтування компонента.
- Дані та повідомлення про помилки зберігаються лише у стані React-компонента.
- PnPjs використовує поточний контекст та авторизацію SPFx.
- Після демонтування компонента його результат більше не оновлює стан React.

### Обробка помилок

| Ситуація | Поведінка |
| --- | --- |
| Відсутній доступ до сайту | Повідомлення з пропозицією перевірити права користувача |
| Помилка мережі або SharePoint API | Безпечне повідомлення без даних відповіді |

## 3. Списки сайту — SharePoint lists

Секція розміщується під **SharePoint site**. Вона автоматично завантажує видимі списки поточного сайту через `PnpSiteListSource`.

Таблиця містить:

- **Name** — назва списку; за наявності адреси це посилання на його стандартне подання;
- **Type** — англомовна назва типу, наприклад `List` або `Document library`;
- **Items** — кількість елементів;
- **Last modified** — дата останньої зміни у форматі `en-US` та часовому поясі UTC.

Приховані системні списки не відображаються. Порожній результат та помилки доступу мають окремі англомовні повідомлення.

## 4. Пошук користувача — User lookup

Секція розміщується під **SharePoint lists** і звертається до списку `Users` поточного сайту. Поле **User ID** очищує всі нецифрові символи. Кнопка **Get user** виконує пошук запису за його числовим ID.

Якщо запис існує, відображаються ID, поле `Title` (за наявності) та повна JSON-відповідь. Якщо запису немає, показується повідомлення **No user record was found for this ID.** Помилка доступу або запиту показується окремим безпечним повідомленням.

## 5. Створення користувача — Create user

Секція розміщується під **User lookup**. У полі **User name** користувач вводить назву нового запису; це значення зберігається у стандартному полі `Title` списку `Users`.

Кнопка **Create user** створює елемент через PnPjs. Після успішного створення форма очищується та показує повідомлення **User record created. New ID: …**. Порожнє поле не створює запис, а помилка прав доступу або запиту має окреме безпечне повідомлення.

    OseledkoYyTest1.module.scss          Вертикальне розміщення та відступ між секціями

`OseledkoYyTest1WebPart` створює джерела товарів і відомостей сайту та відображає контейнер `OseledkoYyTest1`. Контейнер лише розміщує два незалежні компоненти та передає їм джерела даних. Він не зберігає дані, не виконує запитів і не обробляє пагінацію.

```text
OseledkoYyTest1WebPart
└── OseledkoYyTest1 — компонування
    ├── SiteInfo — завантаження та відображення відомостей поточного сайту
    │   └── PnpSiteInfoSource — PnPjs і SharePoint REST API
    ├── SiteLists — завантаження та відображення списків поточного сайту
    │   └── PnpSiteListSource — PnPjs і SharePoint REST API
    ├── UserLookup — пошук запису Users за ID
    │   └── PnpUserLookupSource — PnPjs і SharePoint REST API
    ├── UserCreate — створення запису Users
    │   └── PnpUserCreateSource — PnPjs і SharePoint REST API
    └── Products — стан, завантаження, пагінація та відображення товарів
        └── DummyJsonProductSource — API DummyJSON
```

`Products` не імпортує `SiteInfo`, а `SiteInfo` не залежить від каталогу. Кожен компонент має власний SCSS-модуль, стан завантаження та повідомлення про помилки. Пагінація чи помилка каталогу не очищує дані сайту. Обидві секції використовують кольори поточної теми SharePoint через CSS-змінні та мають стилі для вузьких екранів.

## Локальний запуск

Потрібні Node.js зазначеної версії, npm і доступ до SharePoint-сайту для перевірки у Workbench.

```sh
cd /Users/io/Workspace/sharepointcore/OseledkoYYTest1
npm ci
npm start
```

`npm start` запускає Heft у режимі відстеження змін. У `config/serve.json` налаштовано HTTPS, порт `4321` і сторінку:

[SharePoint Workbench](https://uaenergy0.sharepoint.com/sites/oseledko-yy-test/_layouts/workbench.aspx).

Для локального HTTPS потрібен довірений сертифікат розробника. Якщо його ще не налаштовано, у проєкті доступна команда:

```sh
npx heft trust-dev-cert
```

У Workbench додайте вебчастину **OseledkoYYTest1**. Секції **SharePoint site** та **SharePoint lists** автоматично завантажать дані поточного сайту, **User lookup** дає змогу знайти запис у списку `Users`, **Create user** — створити запис, а **Products** — товари з DummyJSON.

Тимчасове прев’ю на `http://127.0.0.1:8765/`, яке використовувалося під час розробки, не є частиною `npm start` і не замінює перевірку у SharePoint.

## Збирання та пакування

```sh
npm run build
```

Команда послідовно очищує результати попереднього збирання, компілює код і стилі, запускає ESLint та Jest, створює production-збірку й пакує рішення.

Результат:

```text
sharepoint/solution/oseledko-yy-test-1.sppkg
```

Пакет можна використати для розгортання через каталог застосунків SharePoint. Саме збирання не публікує рішення на сайті.

Інші команди:

```sh
npm run clean                  # Очистити результати збирання
npx heft build --production    # Зібрати й перевірити код без тестів і пакування
npx heft test --production     # Зібрати проєкт і запустити тести без пакування
```

## Автоматизовані перевірки

У поточній реалізації є 17 тестів у шести наборах:

- **DummyJsonProductSource** — пагінація, порожній каталог, помилки HTTP, перевірка структури відповіді, мережева помилка та скасування запиту.
- **OseledkoYyTest1** — незалежність секцій: пагінація та помилка каталогу не очищують дані сайту; попередній запит товарів скасовується.
- **SiteInfo** — автоматичне завантаження даних, відображення успішної відповіді та відсутність форми токена.
- **SiteLists** — автоматичне завантаження та відображення списків із посиланням на їхнє стандартне подання.
- **UserLookup** — очищення нецифрового вводу, відображення знайденого запису та повідомлення про відсутній ID.
- **UserCreate** — створення запису, показ ID нового запису та відхилення порожньої назви.

Тести використовують підміну джерел даних і тестові відповіді. Доступ до реального SharePoint-сайту для їх запуску не потрібен. Реальне завантаження перевіряється у SharePoint Workbench під обліковим записом користувача.
